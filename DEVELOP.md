# Developing workspace-webui

Developer notes for the Svelte 5 (runes) SPA. For what the app is and how to
run/deploy it, see `README.md`.

## Commands

```bash
npm install
npm run dev            # vite dev server
npm run test           # vitest (unit tests under src/lib/*.test.ts)
npm run check:svelte   # svelte-check --tsconfig ./tsconfig.json
npm run check:types    # tsc --noEmit
npm run check          # biome check . (lint + format)
npm run build          # vite build -> dist/
```

`check` (biome) is the gate, but two files fail it **on a pristine `main`** and
are therefore pre-existing, not yours: `src/lib/icons.ts` (generated by
`tool/gen-icons.py`, import order) and `src/lib/api-mappers.test.ts` (format).
Run biome on just your files (`npx biome check --fix <files>`) rather than the
whole tree, or you will see those two unrelated failures.

## Architecture

- **Navigation is a FOREST** (`src/lib/nav.ts`). Every `AppPage` kind declares
  exactly one `parentOf`; a visible stack is `ancestry(page)`, a pure function.
  The invariant: **a path contains at most one page of each `kind`**
  (`pushPath` enforces it). Adding a page kind means touching `AppPage`,
  `laneOf`, `parentOf`, `Shell.svelte`'s `componentFor`/`propsFor`, and
  `nav.test.ts`.
- **The Shell shows at most two columns** (`visibleWindow`): a list + a detail.
  A page's `$effect` re-runs when its pane *slides*, so pages cache their data
  in `store.dataLoad(key, load)` (`src/lib/page-cache.ts`) — a slide is a cache
  HIT, no refetch. Call `store.dropData(key)` to force a refresh.
- **Tool cards** (`src/lib/tool-cards/`) are PURE: `cardFor(tool, data, input,
  output)` returns a plain `CardSpec` (fields + an optional `body`), which
  `ToolCard.svelte` renders. Bodies are a closed union in
  `tool-cards/shared.ts`; add a variant there *and* a branch in `ToolCard.svelte`.
- **i18n** (`src/lib/i18n.svelte.ts`) is hand-maintained in this repo (the
  "generated" header is historical — there is no arb source here). Add the key
  to BOTH `en` and `zh`. `i18n-coverage.test.ts` fails the build on any
  un-localized text node or `label`/`title`/`subtitle` literal in a `.svelte`
  file, so new UI strings must go through `t('key')`.
- **DiffView** (`src/lib/components/DiffView.svelte`) parses a unified diff by
  `diff --git`/`--- `/`@@` markers. A producer that concatenates per-file diffs
  WITHOUT a `diff --git` separator (e.g. `sandbox-file-patch`) must split them
  itself first — `splitMultiDiff` in `tool-cards/shared.ts` does this.

## Adding a page

1. Add the kind + `laneOf` + `parentOf` in `nav.ts`.
2. Wire `propsFor` (which `PageProps` fields it needs) and `componentFor` in
   `Shell.svelte`.
3. Create `src/lib/pages/<Name>.svelte`, taking `PageProps`.
4. Add i18n keys (both languages) and extend `nav.test.ts`'s sample list.

## Testing

Pure logic (tool-card mapping, nav, mappers, i18n coverage) is unit-tested with
vitest. When changing a card's output, update `src/lib/tool-cards.test.ts`.
